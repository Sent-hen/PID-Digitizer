```
PID2Graph/
  Complete/<subset>/<id>.{png|jpg}, <id>.graphml      # full sheets  <- source of truth
  Patched/<subset>/<id>/<id>_<k>.{png|jpg,graphml}    # overlapping patches of the same sheets
  Patched/<subset>/<id>/<id>_xy_shifts.npy            # object array [(k, [y_off, x_off]), ...]
```

| subset key | directory | drawings | image | size |
|---|---|---|---|---|
| `dataset_pid` | `Dataset PID` | 500 | PNG RGB | 7168×4561 (300) / 7168×4562 (200) |
| `open100` | `PID2Graph OPEN100` | 12 | PNG RGB | 12 distinct, about 2000–3200 px wide |

Full statistics are in [docs/dataset_stats.md](docs/dataset_stats.md), regenerated by `scripts/inspect_dataset.py`.

**Patched** data: 1500² patches for Dataset-PID/OPEN100 and 2000² for Synthetic, with ≥50% overlap. Patched GraphML adds `border_node` nodes where lines leave a patch. The OPEN100 patches are taken from a rescaled image (140 patches at stride 375 for a 2604-px-wide sheet), not from the Complete PNG resolution. **We use `Complete/` only** and do our own tiling. Patched is redundant for our purposes.

## Annotation format

GraphML, undirected, simple graph (no multi-edges, no self-loops).
- **Node attributes:** `label`, `xmin`, `ymin`, `xmax`, `ymax` in full-image pixels.
- **Edge attribute:** `edge_label` ∈ {`solid`, `non-solid`}.

**Quirk:** GraphML key ids are not stable across files, or even within one file. `d1` is `xmin` in one file and `ymin` in another, and each coordinate may be declared twice (`long` and `double`) with different nodes using different keys. Always resolve by `attr.name`; networkx does this.

### Labels → canonical classes (`configs/data.yaml: label_map`)

| raw label | canonical | meaning |
|---|---|---|
| general, tank, valve, instrumentation, pump, arrow | same | symbol classes (paper Table I) |
| inlet/outlet | `inlet_outlet` | symbol class |
| crossing | `crossing` | structural 8×8 node at a line intersection, T-junction, **or bend** |
| connector | `ankle` | structural 8×8 node, called an "ankle" in the paper. Mostly where a line attaches to a symbol (always degree 2) |
| background | *(dropped)* | 4 degree-0 rectangles per Dataset-PID / OPEN100 sheet covering the frame margins and title block. Stored as `Drawing.ignore_regions` |

There is no text ground truth, no port annotation, and no line polylines (edges are topology only).

### Quirks and anomalies found by the audit

1. **Swapped bbox:** exactly one `background` rectangle per Dataset-PID drawing has `ymin > ymax` (500 total). `BBox` normalizes the order.
2. **Ankles are implicit ports.** Pipes attach to symbols via an ankle node on the symbol boundary (symbol – ankle – … – ankle – symbol). For evaluation, ankles count as graph nodes.
3. **Bends are labelled inconsistently across subsets.**
   - Synthetic marks bends as `crossing` (16 002 degree-2 crossings vs 1 360 of degree ≥3).
   - OPEN100 uses both labels.
   - Dataset-PID uses `crossing` for degree 2–4.
   
   Node AP is class-agnostic, so this doesn't affect the official metric, but per-class structural metrics would be meaningless.
4. **Crossings are connections in the ground truth.**
   - The generator creates a `crossing` node wherever lines intersect (paper §III-D), so two pipes that merely cross become connected through a degree-4 node.
   - Degree-4 crossings: Dataset-PID 17 124, Synthetic 910, OPEN100 only 2 (hand-annotated sheets appear to keep real crossings apart).
   - **Consequence:** the GT does not distinguish junctions from pass-through crossings. The proposal's junction-vs-crossing metric cannot be computed from this GT (see PROGRESS.md, proposed adjustments).
5. **Class coverage differs per subset.** Dataset-PID has no tank, pump or inlet/outlet. Synthetic has no instrumentation or inlet/outlet. Only OPEN100 has all 7 classes, and pump appears 16 times there.
6. **Symbol scale differs ~5× between subsets.** For example, median valve size is 66 px in Dataset-PID, 45 in Synthetic and 20 in OPEN100 at native resolution.
7. **OPEN100 has 54 isolated nodes** (degree 0: 36 instrumentation, 13 general, 5 tank), and all 12 sheets have more than one connected component (off-sheet continuations).
8. **No exact or near duplicates** (ink-map Jaccard; see DECISIONS.md D-004).
   - Nearest-neighbour Jaccard is at most 0.44 (Dataset-PID), 0.30 (Synthetic) and 0.24 (OPEN100), against a grouping threshold of 0.6.
   - No two drawings have identical annotation graphs.
9. **Non-solid lines** make up 4.1% of Dataset-PID edges, 14.6% of Synthetic and 0% of OPEN100.
10. **OPEN100 node ids are not valid GraphML.** Ids like `inlet/outlet3` contain `/`, but GraphML ids must be XML NMTOKENs, so the source files fail the official XSD. The loader maps disallowed characters to `_` (`pid2graph.safe_id`) so all exports validate.
11. In Dataset-PID, text such as notes and tags is rendered but not annotated. Synthetic text is random strings (e.g. `#i)XA8E6`), useless for tag-grammar work.

## Official splits and evaluation protocol

**No train split is released.** Paper Table A3 lists all three released subsets as **test** data. The authors trained on "Synthetic 700" plus 60 real-world P&IDs, neither of which is public. Any model we build must therefore be trained on part of these test sets, so **our numbers are not directly comparable to the paper's.** They come from a different training set and a different (smaller) test set. Our splits are in `splits/`:
- Dataset-PID: 350 / 75 / 75 (train / val / test).
- Synthetic: 174 / 38 / 38.
- OPEN100: 4 train (sheets 0, 6, 7, 9; option B, D-014) and 8 test.

Protocol (paper §III-E, Appendix A1), implemented in `src/pid/eval/`:

| metric | definition | ours |
|---|---|---|
| Symbols mAP | COCO-style AP@IoU 0.5 over the 7 symbol classes, excluding crossings and ankles (IoU 0.75 for Dataset-P&ID in Table A4) | `detection.symbol_map` (pycocotools) |
| Nodes AP | class-agnostic AP@0.5 over symbols + crossings + ankles | `detection.node_ap` |
| Edges mAP | Hungarian node matching on gIoU, no IoU threshold. Per edge class: TP = predicted edge whose mapped GT edge exists with the same class, otherwise FP. FN = GT edge with no predicted edge between the mapped nodes. AP per class, mean over classes. | `connectivity.edge_map_pid2graph` |

Ambiguities and our resolution:
- The paper computes AP with scikit-learn without saying how FNs enter the curve. We use all-point interpolated AP with n_positives = TP + FN (equivalent to appending FNs at score −∞).
- A GT edge matched with the wrong class counts as neither TP nor FN, exactly as in Algorithm A1.
